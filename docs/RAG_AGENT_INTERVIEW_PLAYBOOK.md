# PaperStorm RAG / Agent 面试题库

## 使用说明与指标口径

本题库用于技术面试准备。回答应先给出设计选择，再说明验证方法、失败模式和取舍；不要把一个指标扩展为未经验证的业务结论。

| 类别 | 固定事实 | 正确边界 |
| --- | --- | --- |
| 公开基准 | SciFact recall@10 0.8264（n=300）；QASPER retrieval recall@5 0.5526（n=1309）；独立 full 1451 端到端协议：Answer F1 0.5083、Evidence F1 0.5500、claim support 0.9592、unsupported 0.0214；LongMemEval-S cleaned 500/500 retrieval-only：recall@5 0.8003，P95 359.3 ms。 | 仅对应固定数据、evaluator 与配置；不外推为线上 SLA 或跨领域能力。 |
| 私有领域 pilot | PIM pilot：5 篇论文 / 797 chunks / 50 题；GTE recall@5 0.7200、Answer F1 0.3983、Raw Citation Precision 0.9237（规则型原始引用映射精度，不是语义/人工验证准确率）。 | 是领域链路试点，不是生产准确率，也不代表所有 PIM 资料。 |
| 离线治理指标 | 同一小规模 PIM 索引与固定配置下，HNSW recall@5 1.0000。 | 用于近似索引回归检查；不证明大规模、高并发或任意参数下无损。 |

禁止夸大：SciFact、QASPER、LongMemEval-S cleaned 是公开基准；PIM 是私有领域 pilot；HNSW 的数字是离线治理指标。回答中必须说清数据、样本量、版本、任务定义和限制。

## 一、RAG 基础

### 1. 什么问题适合用 RAG，而不是只靠模型参数？
**参考回答**：知识需要更新、需要私有数据访问、回答必须引用来源或需要权限控制时适合 RAG。它不能保证事实正确，仍需评价召回、证据与生成。
**追问**：什么情况下不应检索？
**考察点**：问题建模、边界意识。
**常见失误**：把 RAG 说成消除幻觉的万能方案。

### 2. RAG 的端到端链路如何拆分？
**参考回答**：解析与切分、索引、查询理解、召回、融合、重排、上下文构造、生成、证据校验、观测与评测。每段都应有输入输出契约。
**追问**：哪一段最值得先优化？
**考察点**：系统分层与诊断思路。
**常见失误**：只讨论 prompt，不讨论数据和检索。

### 3. 如何区分检索失败与生成失败？
**参考回答**：先标注 gold evidence 是否进入候选和最终上下文；未进入是检索或重排问题，已进入但答案错是上下文构造、模型或校验问题。
**追问**：没有人工 gold 怎么办？
**考察点**：可观测性、评测拆解。
**常见失误**：只用最终 Answer F1 判断全部问题。

### 4. 为什么不能只看 Answer F1？
**参考回答**：答案分数会掩盖偶然答对、无依据改写和引用错误；还要看 recall、Evidence F1、claim support、unsupported、延迟和拒答质量。
**追问**：指标冲突时如何取舍？
**考察点**：多目标优化。
**常见失误**：把单分数当作发布门槛。

### 5. PaperStorm 的质量闭环是什么？
**参考回答**：从可追溯 chunk 出发，经混合召回、RRF、重排和压缩进入生成；回答回绑证据与引用，评测产物和 badcase 再反馈规则与数据。
**追问**：闭环中哪些数据应版本化？
**考察点**：工程闭环。
**常见失误**：认为上线日志即可替代离线评测。

## 二、Chunk 与文档解析

### 6. 为什么 chunk 不是固定字符数切分？
**参考回答**：固定长度会切断标题、定义、表格和结论。应尽量遵循结构边界，并保留页码、标题层级、parent 文本和定位信息。
**追问**：chunk 太大或太小各有什么代价？
**考察点**：文档结构理解。
**常见失误**：默认一个长度适合所有文档。

### 7. overlap 的作用和风险是什么？
**参考回答**：overlap 保留跨边界语义，降低断句漏召回；过大则增加冗余、索引成本和近重复证据，可能干扰排序。
**追问**：如何验证 overlap 设置？
**考察点**：实验设计。
**常见失误**：只凭直觉调大 overlap。

### 8. parent-child 检索怎样兼顾精度与上下文？
**参考回答**：先用 child chunk 精确召回，再在 token 预算内展开 parent 邻域；展示的引用仍应定位到真正支持 claim 的 child 或连续原文窗口。
**追问**：parent 太长时怎么办？
**考察点**：上下文预算。
**常见失误**：把整篇文档塞给模型。

### 9. 表格、公式和图表如何处理？
**参考回答**：提取结构化字段、表头和单元格关联，图表保留图号、caption 与数值来源；无法可靠解析时标为风险，不能编造文本证据。
**追问**：PIM pilot 暴露了什么问题？
**考察点**：非纯文本数据治理。
**常见失误**：把 OCR 输出当作无误原文。

### 10. 如何评估 chunk 策略？
**参考回答**：固定 query 与 gold evidence，对比 recall、MRR、nDCG、Evidence F1、上下文 token 与延迟，并分析跨段问题和重复率。
**追问**：为何不只比较 recall？
**考察点**：因果归因。
**常见失误**：同时换切分、模型和 rerank，导致无法归因。

## 三、Embedding

### 11. Embedding 模型选择看哪些合同？
**参考回答**：模型名与 revision、维度、最大长度、query/document 指令、归一化、语言覆盖、许可证和硬件成本都应冻结为 profile。
**追问**：为什么 revision 很重要？
**考察点**：可复现性。
**常见失误**：只记录模型显示名。

### 12. query 与 document 要不要使用不同提示词？
**参考回答**：取决于模型训练契约。有角色提示的模型必须按官方角色编码；没有则不要人为加提示，以免分布偏移。
**追问**：如何防止入口不一致？
**考察点**：接口一致性。
**常见失误**：不同服务各自拼接提示词。

### 13. 如何判断 embedding 的提升是真实的？
**参考回答**：冻结语料、query、评测器和候选深度，只替换 profile；报告样本量、置信范围或至少逐题差异与失败例。
**追问**：30 条 query 的诊断实验能下结论吗？
**考察点**：统计边界。
**常见失误**：小样本最佳分数直接作为最终排名。

### 14. 多语种领域检索有什么额外问题？
**参考回答**：术语翻译、缩写歧义、分词和 query-document 语言不一致会影响召回；需做语言感知 analyzer、术语词典和领域 badcase。
**追问**：PIM 的歧义怎样处理？
**考察点**：领域适配。
**常见失误**：把 PIM 一律解释为同一个含义。

### 15. 向量索引何时需要重建？
**参考回答**：embedding profile、维度、归一化、解析或 chunk 规则、analyzer、ACL 过滤语义变化时都应通过 manifest 触发重建或拒绝加载。
**追问**：只改 metadata 要重建吗？
**考察点**：索引一致性。
**常见失误**：静默复用旧索引。

## 四、Hybrid、BM25、Dense 与 RRF

### 16. 为什么要 Hybrid 检索？
**参考回答**：BM25 擅长精确术语、编号和罕见词，Dense 擅长语义改写；二者错误不完全重合，组合可提升覆盖面。
**追问**：什么情况只用 BM25？
**考察点**：检索器适配。
**常见失误**：宣称 Dense 必然优于 BM25。

### 17. BM25 在中文或专业语料的挑战？
**参考回答**：分词影响巨大，术语被拆散会损失信号。可以使用领域词典、Jieba 或 CJK bigram fallback，并用固定用例回归。
**追问**：分词器升级的风险？
**考察点**：文本分析。
**常见失误**：只看通用英文基准。

### 18. Dense 召回的常见误召回是什么？
**参考回答**：语义相近但实体、时间、限定条件不同的段落会被拉近。可用 metadata filter、query rewrite、rerank 和证据校验补救。
**追问**：filter 为什么要 fail-closed？
**考察点**：权限与正确性。
**常见失误**：过滤失败时回退到全库搜索。

### 19. RRF 为什么适合融合？
**参考回答**：RRF 基于名次而非不可比的原始分数，能稳定合并 BM25 与 Dense 的候选。常数和候选深度仍需固定并评测。
**追问**：RRF 的不足？
**考察点**：融合原理。
**常见失误**：把 RRF 分数解释为概率。

### 20. 如何调 Hybrid 的候选深度？
**参考回答**：先以 recall 和候选去重率确定足够的 candidate_k，再在 rerank、token 与 P95 预算下找拐点，并保存各阶段延迟。
**追问**：candidate_k 越大越好吗？
**考察点**：成本质量权衡。
**常见失误**：忽略 rerank 的尾延迟。

## 五、Rerank

### 21. Rerank 解决什么问题？
**参考回答**：初召回追求高覆盖，reranker 用 query-document 交互模型在较小候选集内提高精排质量，尤其能处理限定条件。
**追问**：为什么不对全库 rerank？
**考察点**：计算复杂度。
**常见失误**：把 rerank 当作召回替代品。

### 22. 如何评估 reranker 值不值得？
**参考回答**：在相同初召回候选上对比 nDCG、MRR、Evidence F1、最终答案和 P95；同时记录模型、批量和硬件。
**追问**：只提升 nDCG 就上线吗？
**考察点**：端到端评价。
**常见失误**：不看延迟和证据退化。

### 23. reranker 可能造成哪些失败？
**参考回答**：它可能把互补证据压掉、偏好表面相似文本或放大训练域偏差。需要多 chunk 证据、badcase 与回退策略。
**追问**：如何保留多样性？
**考察点**：排序风险。
**常见失误**：只取前一条最高分段落。

### 24. Cross-Encoder 与 bi-encoder 的分工？
**参考回答**：bi-encoder 适合离线编码和大规模初召回；Cross-Encoder 精度高但计算重，适合小候选集 rerank。
**追问**：能否缓存 rerank？
**考察点**：架构权衡。
**常见失误**：忽略 query 变化导致的缓存失效。

### 25. rerank 服务故障如何降级？
**参考回答**：设定超时、熔断和可观测事件，按策略回退到融合排序并在结果中标注降级；不要静默伪装为正常 rerank。
**追问**：何时应该直接拒答？
**考察点**：可靠性。
**常见失误**：无限重试阻塞主请求。

## 六、证据、引用与冲突

### 26. 什么是可用证据？
**参考回答**：证据应能直接支撑具体 claim，具有文档、段落或页码 provenance，并可在用户可见上下文中回放；相关不等于支撑。
**追问**：如何处理间接证据？
**考察点**：事实归因。
**常见失误**：用一篇主题相关文献为所有结论背书。

### 27. Raw Citation Precision 0.9237（规则型原始引用映射精度，不是语义/人工验证准确率）可以怎么说？
**参考回答**：它是 PIM 私有领域 pilot、50 题、固定规则下的 Raw Citation Precision 0.9237，即规则型原始引用映射精度，不是语义/人工验证准确率；它也不是线上引用正确率，更不表示每条引用绝对正确。
**追问**：为什么不能用它当产品 KPI？
**考察点**：指标真实性。
**常见失误**：省略数据规模与 pilot 标签。

### 28. 多个来源相互冲突时如何回答？
**参考回答**：保留冲突来源、比较时间、研究设计和适用条件，明确报告分歧；若无法判定，不合并成确定结论。
**追问**：系统应返回几条引用？
**考察点**：不确定性表达。
**常见失误**：让模型投票选一个“真相”。

### 29. 如何防止引用幻觉？
**参考回答**：生成只能选择检索白名单中的证据 ID，后处理检查 ID、定位、文本蕴含和重复；校验失败应剔除或降级回答。
**追问**：白名单的局限？
**考察点**：治理设计。
**常见失误**：只要求模型输出方括号引用。

### 30. claim support 0.9592 与 unsupported 0.0214 如何解释？
**参考回答**：它们是 QASPER 独立 full 1451 端到端协议下的声明支持与未支持比例，反映该 evaluator 和配置的证据一致性；不能等同于所有回答的真实正确率。
**追问**：为什么二者不必加和为 1？
**考察点**：指标定义。
**常见失误**：把不同统计口径硬凑成准确率。

## 七、Memory

### 31. RAG 知识库与 Memory 有何区别？
**参考回答**：知识库保存外部文档，Memory 保存会话或用户交互形成的事实、偏好和事件；两者生命周期、权限、时间有效性不同。
**追问**：哪些内容不该写入 Memory？
**考察点**：数据治理。
**常见失误**：把全部对话原文永久存储。

### 32. 如何设计 Memory 的数据模型？
**参考回答**：可分 episode、fact、entity、provenance 与有效时间，记录来源、写入理由、置信度和撤销状态，使检索结果可解释可删除。
**追问**：事实更新怎么做？
**考察点**：时间语义。
**常见失误**：新旧事实直接覆盖而不留历史。

### 33. Memory 检索为什么也需要 Hybrid？
**参考回答**：会话记忆既有实体和精确名称，也有语义表达与时间约束；可结合 BM25、embedding、entity、time、RRF 和 MMR 多样性。
**追问**：如何避免旧主题干扰？
**考察点**：检索排序。
**常见失误**：只按向量相似度取记忆。

### 34. LongMemEval-S cleaned 500/500 retrieval-only：recall@5 0.8003，P95 359.3 ms 说明什么？
**参考回答**：它说明该固定 LongMemEval-S cleaned 500/500 retrieval-only 协议下前五条记忆候选覆盖 gold 的程度，P95 359.3 ms；它不能表述成端到端回答准确率。
**追问**：P95 359.3 ms 又说明什么？
**考察点**：任务与性能边界。
**常见失误**：将 recall 与生成质量混为一谈。

### 35. Memory 的删除和权限如何落地？
**参考回答**：按用户、会话、租户和来源建立 ACL；检索过滤 fail-closed，删除需要覆盖原记录、派生向量和缓存，并留下审计事件。
**追问**：异步删除期间怎么保证不泄漏？
**考察点**：隐私工程。
**常见失误**：只从主表删除，不清理索引。

## 八、Context Compression

### 36. Context Compression 解决什么问题？
**参考回答**：它在上下文预算内保留与问题有关的证据，减少无关 token、延迟和干扰；不是无损摘要，也不能替代原文追溯。
**追问**：什么时候不应压缩？
**考察点**：上下文策略。
**常见失误**：默认压缩所有内容。

### 37. 如何防止压缩丢掉限定条件？
**参考回答**：保留引用锚点、数值、否定词、时间和实体，压缩后做与原文的蕴含或 span 回绑校验；失败时回退原文。
**追问**：回退会怎样影响延迟？
**考察点**：正确性优先级。
**常见失误**：只评估摘要流畅度。

### 38. 压缩失败的定义是什么？
**参考回答**：输出为空、超预算、无法回绑来源、关键 claim 不再被原文支持或模型调用异常，都应是可观测失败并触发策略回退。
**追问**：失败率该怎样展示？
**考察点**：错误建模。
**常见失误**：吞掉异常并返回空上下文。

### 39. 如何给 context 分配 token 预算？
**参考回答**：先预留 system、问题、工具结果和生成空间，再根据证据相关性、来源多样性和 parent-child 关系分配，且设硬上限。
**追问**：长问题如何处理？
**考察点**：资源控制。
**常见失误**：预算只留给检索结果。

### 40. 怎样评估 compression？
**参考回答**：比较压缩前后的 Evidence F1、Answer F1、citation 校验通过率、token、P50/P95，并人工检查关键失败例。
**追问**：为何不只看 token 降幅？
**考察点**：质量效率平衡。
**常见失误**：压缩率最高就认为最优。

## 九、Agent Runtime、Tool 与 Multi-Agent

### 41. Agent Runtime 的核心职责是什么？
**参考回答**：管理状态、路由、工具调用、预算、超时、重试、取消、事件流和恢复，并为每个阶段产生可观测边界。
**追问**：为什么不能把这些都放在 prompt？
**考察点**：运行时设计。
**常见失误**：把 Agent 等同于循环调用模型。

### 42. Tool 调用如何保证安全和可恢复？
**参考回答**：定义输入 schema、权限与副作用等级，设置超时、幂等键、重试上限和审计；有写操作的工具必须区分已执行与未知状态。
**追问**：网络超时后能否重试？
**考察点**：分布式系统常识。
**常见失误**：对非幂等写操作盲目重试。

### 43. Multi-Agent 何时有价值？
**参考回答**：当任务可并行、角色边界清晰且汇总成本低时有价值，例如检索、验证和报告分工；否则单 Agent 更易控制。
**追问**：如何防止互相循环调用？
**考察点**：协作边界。
**常见失误**：为显得复杂而拆很多 Agent。

### 44. Agent 状态如何设计？
**参考回答**：状态应显式包含用户意图、检索计划、证据、工具结果、错误、预算和版本，区分可持久化事实与瞬时缓存。
**追问**：checkpoint 保存什么？
**考察点**：可恢复性。
**常见失误**：把完整 prompt 和密钥都写进状态。

### 45. 如何处理 Agent 的无限循环或工具风暴？
**参考回答**：设最大步数、总 token/时间预算、工具调用配额、重复动作检测和人工升级路径；异常终止也要留下最后状态。
**追问**：如何选择默认阈值？
**考察点**：风险控制。
**常见失误**：只依赖模型自我停止。

## 十、Langfuse 与可观测性

### 46. Langfuse 在系统里扮演什么角色？
**参考回答**：用于 trace、嵌套 observation、版本属性、token/延迟和 score 的分析与 badcase 回放；它不是 Agent runtime，也不替代 benchmark evaluator。
**追问**：为什么还保留本地审计事实源？
**考察点**：可观测性边界。
**常见失误**：把平台 dashboard 当作唯一真相。

### 47. trace 应如何关联一次请求？
**参考回答**：用请求或会话 ID 关联 trace，给检索、rerank、compression、generation、tool 等阶段建立 span，并附版本、环境、检索器和匿名化标签。
**追问**：哪些字段不能上传？
**考察点**：数据安全。
**常见失误**：记录未脱敏用户原文和密钥。

### 48. 为什么采用 fail-open？
**参考回答**：Langfuse 凭据、网络或 exporter 失败时，观测不应中断用户主链路；同时本地记录失败事件并告警。高风险业务可另设更严格策略。
**追问**：fail-open 有什么代价？
**考察点**：可用性权衡。
**常见失误**：以为 fail-open 不需要监控。

### 49. 如何用 Langfuse 做 badcase 分析？
**参考回答**：按版本、数据集、retriever、延迟和评分过滤 trace，回放 query、候选、证据与答案，归类为解析、召回、排序、压缩或生成问题。
**追问**：如何避免 cherry-pick？
**考察点**：诊断纪律。
**常见失误**：只展示好看的示例。

### 50. 线上 trace 能替代离线 Benchmark 吗？
**参考回答**：不能。线上 trace 适合发现分布变化与排障，离线 Benchmark 通过固定数据和 evaluator 比较版本；二者互补。
**追问**：何时触发回归评测？
**考察点**：发布治理。
**常见失误**：只看调用成功率。

## 十一、Benchmark 与评估

### 51. 如何解释 SciFact recall@10 0.8264（n=300）？
**参考回答**：这是公开 SciFact 固定评测协议、n=300 下，前十候选覆盖相关证据的检索指标；应同时报告数据版本和设置，不宣称为所有科学问题的准确率。
**追问**：为何是 recall@10 而不是 Answer F1？
**考察点**：指标与任务匹配。
**常见失误**：把 recall 读成答案正确率。

### 52. QASPER retrieval recall@5 0.5526（n=1309）与 full 1451 指标有什么关系？
**参考回答**：QASPER retrieval recall@5 0.5526（n=1309）衡量前五条检索证据覆盖；独立 full 1451 端到端协议的 Answer F1 0.5083、Evidence F1 0.5500 衡量端到端回答与证据，不能混作同一指标。
**追问**：为什么端到端分数可能低于召回？
**考察点**：流水线误差传播。
**常见失误**：忽略 generation 与证据选择损失。

### 53. 如何建立发布门槛？
**参考回答**：先冻结基线和数据，设质量下限、回归容忍度、延迟和失败率门槛；任何提升需附 badcase、成本和可复现命令。
**追问**：所有指标都要提高吗？
**考察点**：发布决策。
**常见失误**：只看平均分，不看严重回归。

### 54. PIM pilot 的正确价值是什么？
**参考回答**：PIM pilot：5 篇论文 / 797 chunks / 50 题，价值是暴露领域术语、图表、跨 chunk 证据和引用问题；GTE recall@5 0.7200 等结果仅适用于该私有领域 pilot。
**追问**：下一步如何增强可信度？
**考察点**：外部效度。
**常见失误**：把 50 题当作行业基准。

### 55. 人工评测怎样减少偏差？
**参考回答**：预注册 rubric、盲评、双人标注与仲裁，区分正确性、完整性、证据和表达；保存样本和一致性统计。
**追问**：LLM-as-a-Judge 能否替代人？
**考察点**：评测可信度。
**常见失误**：不验证 judge 与人工的一致性。

## 十二、稳定性、并发、项目难点与项目成就

### 56. RAG 服务的并发瓶颈通常在哪里？
**参考回答**：解析、embedding、ANN、rerank、模型调用、数据库连接和流式回传都可能成为瓶颈。要分别测队列、P50/P95、超时和资源占用。
**追问**：为什么平均延迟不够？
**考察点**：性能分析。
**常见失误**：只压测单请求。

### 57. 如何设计稳定性与降级？
**参考回答**：为每层设超时、熔断、限流、重试上限与可解释降级，例如 rerank 失败回退融合排序，观测失败 fail-open；权限过滤不能降级为放开。
**追问**：什么是必须 fail-closed 的路径？
**考察点**：可靠性与安全性。
**常见失误**：所有失败都重试。

### 58. HNSW recall@5 1.0000 如何在面试中表述？
**参考回答**：在 PIM 小规模离线索引、固定构建与查询参数下，HNSW recall@5 为 1.0000，用于验证该配置的 ANN 质量。它不是大规模性能或无损索引的承诺。
**追问**：上线前还要测什么？
**考察点**：近似检索边界。
**常见失误**：删掉“小规模、离线、固定参数”。

### 59. 项目中最有代表性的难点是什么？
**参考回答**：难点是把“回答看起来合理”转化为可定位的系统问题：需要将 chunk、检索、重排、压缩、证据、生成、延迟和 trace 串成同一条可复现实验链路。
**追问**：你亲自做了哪个关键决策？
**考察点**：项目难点、责任归属。
**常见失误**：用团队成果替代个人贡献，或不说明证据。

### 60. 你会如何总结项目成就？
**参考回答**：我会说完成了可评测、可治理的 RAG Agent 工程闭环，并准确报出公开基准、私有领域 pilot 和离线治理指标的边界；成果在于可复现和可诊断，而非未经验证的生产收益。
**追问**：下一阶段最重要的工作？
**考察点**：项目成就、诚实表达与路线图。
**常见失误**：宣称“零幻觉”“生产级准确率”或虚构业务收益。
